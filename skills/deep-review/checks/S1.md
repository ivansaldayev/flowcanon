# S1 — Skill Guidelines Compliance

Use when the artifact under review is a skill (SKILL.md and its bundled files). Check the draft against the skill-creator guidelines:

- Frontmatter: `name` matches the directory; `description` states both what the skill does AND when to trigger — concrete contexts, strong enough not to under-trigger.
- Body: imperative form; no unexplained ALL-CAPS MUST/NEVER — instructions explain the why.
- Progressive disclosure: SKILL.md stays lean (<500 lines); large references split into bundled files with clear pointers; deterministic repetitive steps belong in scripts.
- Claims about the environment (tool names, paths, commands): verify against the real environment before flagging — a 🔴 like «unknown tool name» must be reproduced, not assumed.
- Self-audit trap: if the skill under review is also loaded in your own context as instructions, its text appears twice — verify any «duplicated rule» finding by grep against the file before reporting it.
