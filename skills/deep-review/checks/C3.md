# C3 — Scale Projection

Imagine this code lives for 2 years, is used in 50 places, and is maintained by someone who never saw the original.

- What will break when requirements change slightly?
- What will be copy-pasted because it's too hard to extend?
- What implicit assumptions will be violated by a new team member?
- Where is tribal knowledge required to avoid bugs?
- What stops being acceptable when the data is 100× bigger: a query or request inside a loop, a whole collection loaded to filter in memory, a new query shape with nothing to index it, an unbounded list rendered at once?
