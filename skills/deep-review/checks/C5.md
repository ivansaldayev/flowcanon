# C5 — Cross-Project Consistency

- Schema/contract alignment between layers: persisted schemas and API contracts match between producer and consumers (field names, types, required/optional).
- Component/helper reuse: are existing shared components used, or duplicated?
- Direct library imports where a project wrapper exists.
- Code duplication between files/modules.

Find the pairs yourself — nothing lists them for you:

- For each changed schema, type, or route: locate every counterpart across the boundary — the client model of a server schema, the consumers of a route, the shared type a payload is built from — by field name, path, and type name, in every project of the repository, not only the one changed.
- For each new import of a UI, HTTP, storage, or navigation library: check whether the project already routes that concern through a wrapper the rest of the code uses (a components, hooks, api, or store layer) — the `CLAUDE.md` chain usually names it.
- Where the project declares layers (persistence → logic → transport, or any other order): flag a change that reaches past a layer directly while the same operation already exists in the layer it skipped. The declared rules themselves are C6's; C5 flags the bypass.
